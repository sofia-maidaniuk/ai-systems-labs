
# AI Marketing Strategist

AI Marketing Strategist — локальний вебзастосунок
для створення рекламних матеріалів на основі
маркетингового брифу.

Застосунок працює з локальною мовною моделлю
Qwen3-4B через Ollama та OpenAI-сумісний API.

## Можливості

1. Створення маркетингового брифу продукту.
2. Аналіз трьох сегментів цільової аудиторії.
3. Генерація 10 рекламних хуків.
4. Вибір найкращих хуків.
5. Створення текстів рекламних креативів.
6. AI-редагування сегментів, хуків і креативів.
7. Експорт результатів у JSON.

## Використані технології

- Python
- Streamlit
- Ollama
- Qwen3-4B-Instruct-2507 Q8_0
- OpenAI Python SDK
- Pydantic

Усі запити до мовної моделі виконуються
локально через http://localhost:11434/v1.

## 1. Встановлення

Для роботи застосунку потрібні Python 3 та Ollama.

Створіть і активуйте віртуальне середовище:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Встановіть необхідні Python-бібліотеки:

```bash
python -m pip install streamlit
python -m pip install openai
python -m pip install pydantic
```

## 2. Завантаження моделі

```bash
ollama pull qwen3:4b-instruct-2507-q8_0
```

Для створення конфігурації з контекстом
8192 токени використати файл Modelfile.hooks:

```bash
ollama create qwen3:4b-instruct-2507-q8-8k -f app/Modelfile.hooks
```

Перевірити доступні моделі:

```bash
ollama list
```

За потреби запустити сервер Ollama:

```bash
ollama serve
```

Якщо застосунок Ollama вже запущений
і сервер доступний, додатково виконувати
ollama serve не потрібно.

## 3. Запуск застосунку

Із кореневої папки проєкту виконати:

```bash
python -m streamlit run app/main.py
```

Відкрити у браузері:

http://localhost:8501

## 4. Робота із застосунком

1. Заповнити маркетинговий бриф.
2. Вибрати модель та проаналізувати ЦА.
3. Переглянути сегменти й за потреби внести AI-правки.
4. Згенерувати 10 рекламних хуків.
5. Вибрати хуки для рекламних креативів.
6. Згенерувати тексти креативів.
7. За потреби відредагувати результат через AI.
8. Завантажити результати у форматі JSON.

## 5. Параметри генерації

Для аналізу ЦА:
- temperature: 0.2
- max_tokens: 3200

Для рекламних хуків:
- temperature: 0.5
- max_tokens: 2800

Для рекламних креативів:
- temperature: 0.4
- max_tokens: 700 на креатив

Для AI-редагування:
- temperature: 0.3
- max_tokens: 900

Для великих запитів використовується
конфігурація моделі з num_ctx = 8192.

Низька temperature використовується
для більш послідовного аналізу.

Вища temperature для хуків дозволяє
отримувати різноманітніші формулювання.

Ліміти max_tokens запобігають надмірно
довгій генерації та обмежують використання
обчислювальних ресурсів.

Контекст 8192 дозволяє передавати бриф,
аналіз ЦА та промпт в одному запиті.
Початкове вікно 4096 було недостатнім.

## 6. Обробка помилок

Під час генерації відображається
індикатор очікування.

Застосунок обробляє:
- недоступність сервера Ollama;
- таймаут відповіді;
- HTTP-помилки сервера;
- перевищення ліміту токенів;
- некоректні або порожні відповіді;
- невідповідність результату JSON-схемі.

## 7. Особливості реалізації

Для різних етапів використовуються
окремі системні промпти.

Результати генерації перевіряються через
Pydantic та зберігаються у Streamlit Session State.

Застосунок не потребує зовнішнього
хмарного API для генерації відповідей.
